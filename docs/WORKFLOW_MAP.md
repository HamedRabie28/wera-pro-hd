# WORKFLOW MAP — خرائط التدفقات المرجعية

> **الوثيقة:** WERA-WM-001 · **الإصدار:** 1.0 · **التاريخ:** 2026-11-01
> التدفقات هنا عقود سلوك تُترجم Use Cases في G1+ واختبارات قبول. كل انتقال حالة مذكور صراحةً.

---

## 1. مسار البيع الكامل (Sales Journey) — من المسح إلى الترحيل

```
(1) التهيئة ── (2) بناء السلة ── (3) التحقق الخادمي ── (4) الدفع ── (5) الترحيل الذري ── (6) ما بعد البيع
```

1. **التهيئة:** فتح POS → التحقق من الجلسة والمحطة والفرع → وردية مفتوحة؟ (إن لا توجد وسياسة النشاط تتطلب: إجباري فتح الوردية قبل البيع) → التركيز على حقل الباركود.
2. **بناء السلة:** مسح باركود (Exact Match) أو بحث متدرج (باركود → SKU → PLU → نص محدود بـ Debounce) أو صنف وزني (انظر مسار الوزن) أو اختيار صيغة بيع عند تعدد SKUs. دمج السطور فقط عند تطابق SKU/الوحدة/السعر/الضريبة/الدفعة. تعديل السعر والخصم بصلاحية وسبب (D-06).
3. **التحقق الخادمي (إعادة حساب كاملة — لا يُقبل إجمالي من العميل):** الأسعار من قائمة السعر الفعالة زمنيًا · الضريبة وفق سياسة D-01 · الخصومات بلا تكرار · الرصيد وسياسة السالب D-03 · حد الائتمان للآجل D-05.
4. **الدفع:** نقد (فكة محسوبة) · بطاقة (مزود حقيقي — عند UNKNOWN/timeout استعلام بالمرجع قبل أي إعادة) · Split (كل وسيلة بمرجع مستقل) · آجل (عميل + حد + صلاحية). الحالات: INITIATED→PENDING→AUTHORIZED→CAPTURED→SETTLED أو DECLINED/FAILED_CONFIRMED/UNKNOWN/CANCELLED/REFUNDED.
5. **الترحيل الذري داخل Transaction واحدة على الخادم:** رقم فاتورة فريد (تسلسل لكل فرع/وردية) · لقطة سعر/خصم/ضريبة/وحدة/عامل تحويل/تكلفة · حركة مخزون بوحدة أساسية لكل سطر (كيس=1، علبة=12) · قيد/أثر خزينة للوردية · سجل تدقيق — و`idempotency_key` يمنع أي تكرار عند إعادة المحاولة.
6. **ما بعد البيع:** طباعة اختيارية (PrintJob مستقل — فشلها لا يلغي البيع ويُعاد بدون تكرار) · إعادة تهيئة السلة بعد نجاح الترحيل فقط.

**حالات الفاتورة:** `DRAFT → SUSPENDED → (استعادة) DRAFT → POSTED` · الإلغاء قبل الترحيل بسبب موثق · عكس المرحل بمعكوس مالي مرتبط بالأصل — لا حذف أبدًا.

## 2. مسار المرتجع/الاستبدال

بحث الفاتورة الأصلية (بمرجع/عميل حسب صلاحية) → عرض ما بيع وما رُجع سابقًا → اختيار كميات/أوزان ≤ المتبقي → سبب + حالة صنف (يعود للمخزون / هالك) → اعتماد وفق D-04 → رد المال بوسيلة الأصل (استثناء نقدي بقرار موثق) أو استبدال بفارق محسوب → مستند مرتبط بالأصل يخصم المخزون/الضريبة/الخزينة مرة واحدة.

## 3. مسار الشراء والاستلام

سلة/أمر شراء (مسودة قابلة للاستعادة) → **استلام** يعتمد: مراجعة كميات ووحدات وتحويلات (علبة ×12 → 12 وحدة أساسية، عدد صحيح مضمون) → ترحيل حركة مخزون IN موثقة → فاتورة مورد (قد تختلف عن الاستلام) → سداد جزئي/كلي بتوزيع على فواتير ≤ المتبقي → مرتجع مورد مرتبط بالأصل. **قاعدة:** إنشاء فاتورة المورد وحدها لا يزيد المخزون — الحدث المعتمد هو الاستلام.

## 4. مسار الجرد والتسوية

اختيار نطاق (مخزن/فئات) → تجميد منطقي أو لقطة رصيد → عد فعلي (كميات بوحدة أساسية) → مقارنة فعلي/متوقع → **مستند تسوية** بفرق موثق وسبب وموافقة وفق الصلاحية → ترحيل حركات تسوية → تقرير فروق يبقى ظاهرًا في التاريخ. ملاحظة: Quick Stock Adjustment من POS تفتح مستند تسوية مستقلًا مسبق التعبئة — لا تعديل رصيد حر أبدًا.

## 5. دورة حياة الوردية والخزينة

**الحالات:** `OPEN → CLOSING_PENDING → RECONCILED → HANDED_OVER → CASHIER_CONFIRMED → TREASURY_ACCEPTED → CLOSED` (مع `DISCREPANCY` كحالة فرق قائمة حتى المعالجة).

- **فتح:** كاشير + محطة + رصيد افتتاحي موثق + وقت.
- **أثناء:** مبيعات نقد/بطاقة/آجل منفصلة، مرتجعات، مصروفات وسحب/إيداع مصرح، فتح درج بصلاحية وسبب (وقت الطلب ووقت استجابة الجهاز؛ وقت الإغلاق UNKNOWN ما لم يوفر الجهاز مستشعرًا).
- **إغلاق:** نقد متوقع = افتتاحي + مبيعات نقدية − مرتجعات نقدية + إيداعات − سحب/مصروفات → فعلي معدود → فارق زائد/ناقص بسبب → اعتماد. **الإغلاق التشغيلي ≠ استلام الخزينة** — حالتان مستقلتان ومنع ترحيل مزدوج.
- **التسليم:** سند تسليم خزينة وحالة قبول مستقلة. الفروق تظل ظاهرة تاريخيًا حتى المعالجة.

## 6. الطرق الست لإدخال الوزن إلى السلة (Weight Sale Workspace)

| # | الطريقة | مصدر الوزن الموسوم | الشروط والأصول الحاكمة |
|---|---|---|---|
| 1 | **قراءة مباشرة من الميزان** | `SCALE_READING` | ميزان متصل فعلًا + قراءة مستقرة + حديثة (عمر قراءة محدود بحد صلاحية معتمد)؛ تعرض الاتصال والثبات والوقت وTare/Net؛ لا تُقبل قراءة قديمة أو من جهاز غير متصل |
| 2 | **إدخال وزن يدوي** | `MANUAL_WEIGHT` | صلاحية/إعداد يسمح + تسجيل المستخدم والوقت وسبب التعديل عند الحاجة؛ **لا توصف أبدًا كقراءة ميزان** |
| 3 | **بيع بمبلغ مستهدف** | `AMOUNT_DERIVED` | الوزن الحسابي = المبلغ ÷ سعر الوحدة — مثال مرجعي: 200 EGP/kg ومبلغ 70 EGP → **350 g قبل سياسة خطوة الوزن والتقريب (D-07)**؛ تعرض القيمة المتوقعة والفرق عند قراءة وزن فعلي، ولا يُعدل سعر ولا خصم خفي لمطابقة المبلغ |
| 4 | **وزن سريع** | `MANUAL_WEIGHT` | أزرار مثل 1kg/500g/250g/125g قابلة للتهيئة لكل منتج؛ لا يظهر زر لا يوافق دقة المنتج وخطوة الميزان؛ ليست SKU عبوة |
| 5 | **ملصق باركود موزون** | `WEIGHT_LABEL` | يحلل `VariableWeightBarcodeProfile` (بادئة/طول/موضع PLU/وزن أو سعر/وحدة/رقم تحقق)؛ رفض موثق للصيغة المجهولة أو رقم التحقق الخاطئ أو كود صنف غير معروف — **لا تخمين**؛ يحتفظ السطر بالقيم المشفرة |
| 6 | **عبوة موزونة مسبقًا** | `PACK/COUNT` | عبوة SKU مستقلة بوزن ثابت وباركود مستقل تُعامل كصيغة بيع معبأة، لا كوزن حي؛ الفاتورة والمخزون يميزانها |

**قواعد الحساب والتخزين (كل الطرق):** decimal/NUMERIC فقط · وحدة مخزون أساسية صريحة (gram) وعامل تحويل موحد · لا خصم مخزون عند فتح النافذة — الخصم عند الترحيل/الحجز · وزن 0 أو سالب أو خارج حدود المنتج/الجهاز = رفض · فشل إضافة الوزن لا يغير سطورًا أخرى · حفظ: وزن المصدر + وحدة الإدخال + معامل التحويل + الكمية الأساسية + سعر الوحدة + المبلغ + مصدر الوزن. مثال الدقة الإضافي: وزن 1.275 kg يُحسب وفق السعر ودقة الوزن وسياسة التقريب المعتمدة دون أي تقريب مبكر قبل السعر.

## 7. حالات الأجهزة والخدمات (تسري في كل التدفقات)

`CONNECTED · DISCONNECTED · UNKNOWN · NOT_CONFIGURED · ERROR` مع وقت آخر فحص. لا تُعرض حالة ناجحة من مجرد وجود إعداد، ولا يعلن اتصال دون فحص فعلي حديث موثق (البرومت §0.1 ق7 وق11).
