>
> هذا الدليل يغطي: بناء حزمة التثبيت، تثبيتها على Windows 10/11، التثبيت الصامت المؤسسي، تشخيص أي مشكلة، وشرح كامل لعلاج قضية «التشغيل في الخلفية دون نافذة».

## 1. المتطلبات

### على جهاز البناء (مرة واحدة فقط)

| الأداة | الإصدار | أمر التثبيت |
|---|---|---|
| .NET SDK | 10.0.4xx | `winget install Microsoft.DotNet.SDK.10` |
| Inno Setup | 6.3 فأحدث | `winget install JRSoftware.InnoSetup` |

> Inno Setup 6.3+ مطلوب لدعم `RightToLeft=yes` (معالج عربي RTL أصيل). سكربت البناء يتحقق من الإصدار ويوقف عند القِدم.

### على جهاز العميل (الحد الأدنى)

| البند | الحد |
|---|---|
| نظام التشغيل | Windows 10 بناء 17763 (إصدار 1809 — أكتوبر 2018) أو أحدث · أو Windows 11 بأي إصدار |
| المعالج | x64 أو x64-متوافق (يشمل ARM64 بمحاكاته) |
| المساحة | ~600 MB (الحزمة المعزولة تشمل كل التشغيليات) |
| متطلبات مسبقة | **لا شيء** — لا .NET ولا Windows App Runtime ولا VC++ (الأخير مدمج اختياريًا داخل الحزمة عند الحاجة) |

> **لماذا لا يعمل على ويندوز أقدم من 1809؟** إطار واجهة WinUI 3 / Windows App SDK من مايكروسوفت يشترط معماريًا Windows 10 1809+. كل إصدارات ويندوز 10 الصادرة بعد أكتوبر 2018 وكل إصدارات ويندوز 11 مدعومة — أي عمليًا كل ويندوز حديث قيد الاستخدام. عند محاولة التثبيت على نسخة أقدم تظهر رسالة عربية واضحة تشرح السبب بدل الفشل الصامت.

## 2. بناء الحزمة

### الطريقة أ — سطر واحد على ويندوز

```powershell
powershell -ExecutionPolicy Bypass -File installer\build-installer.ps1
```

الناتج: `installer\output\WeraProSetup-0.3.0-win-x64.exe` (مع طباعة SHA256 للتحقق).

### الطريقة ب — GitHub Actions (بدون ويندوز محلي)

ادفع وسمًا: `git tag v0.3.0 && git push origin v0.3.0` — سير عمل `Installer — Build Windows Setup` يبني الحزمة على عدّاء windows ويرفعها **Artifact** وعند الوسم **GitHub Release** جاهزة للتحميل.

### ماذا يفعل السكربت بالضبط؟

1. `dotnet publish src/WeraPro.Desktop -c Release -r win-x64 -p:Platform=x64 --self-contained true`
   → نشر **معزول ذاتيًا** يتضمن .NET 10 + Windows App SDK (لا متطلبات على جهاز العميل).
2. تنزيل `vc_redist.x64.exe` الرسمي من مايكروسوفت (مكون اختياري يُثبَّت **عند الحاجة فقط**).
3. ترجمة `WeraProSetup.iss` عبر ISCC بضغط `lzma2/max`.

## 3. التثبيت

### تفاعلي (المستخدم النهائي)

1. تشغيل `WeraProSetup-0.3.0-win-x64.exe` — يظهر المعالج **بالعربية من اليمين لليسار** بهوية WERA PRO HD البصرية.
2. اختيار نطاق التثبيت: «لكل المستخدمين» (افتراضي، يحتاج موافقة مدير) أو «للمستخدم الحالي فقط».
3. مجلد افتراضي: `C:\Program Files\WERA PRO HD`.
4. خيار أيقونة سطح المكتب (لكل المستخدمين أو للحالي).
5. «تثبيت» ثم «تشغيل WERA PRO HD الآن» (اختياري).
6. تظهر **نافذة تسجيل الدخول فورًا** — لا عمل خلفي صامت.

### صامت (نشر مؤسسي / MDM / SCCM)

```bat
WeraProSetup-0.3.0-win-x64.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /ALLUSERS
```

| المفتاح | الوظيفة |
|---|---|
| `/VERYSILENT` | بلا واجهة إطلاقًا |
| `/SUPPRESSMSGBOXES` | كتم صناديق الرسائل |
| `/NORESTART` | عدم إعادة التشغيل أبدًا |
| `/ALLUSERS` أو `/CURRENTUSER` | فرض نطاق التثبيت |
| `/DIR="مسار"` | مجلد مخصص |
| `/LOG="مسار"` | سجل تثبيت تفصيلي |
| `/TYPE=full` أو `custom` | نوع التثبيت (مع VC++ أو بدونه) |

**رمز الخروج `0` = نجاح** — متوافق مع أدوات النشر المؤسسي.

### الترقية

شغّل حزمة الإصدار الأحدث فوق القديم — نفس `AppId` يعني: يُغلق التطبيق قيد التشغيل بأمان، تُستبدل الملفات، ويُعاد فتحه بعدها. الإعدادات والسجلات تبقى.

### الإزالة

«إعدادات → تطبيقات → WERA PRO HD → إلغاء التثبيت» أو من اختصار قائمة ابدأ. تُترك بيانات المستخدم (سجلات `%LOCALAPPDATA%\WERA_PRO_HD`) عمدًا.

## 4. قضية «يعمل في الخلفية دون ظهور النافذة» — التشخيص والعلاج النهائي

### الأسباب الجذرية الأربعة (اكتشُفت وعولجت كلها)

| # | السبب الجذري | العلاج المطبق (2026-11-07) |
|---|---|---|
| 1 | المشروع كان يُبنى وضع **MSIX-packaged** (لا يوجد `WindowsPackageType=None`)؛ تشغيل الـexe مباشرة دون تثبيت MSIX يفشل **صامتًا**: عملية حية بلا نافذة | `WindowsPackageType=None` في `WeraPro.Desktop.csproj` — وضع Unpackaged رسمي مدعوم |
| 2 | `appsettings.json` كان يُقرأ **نسبيًا من دليل العمل**؛ الإطلاق من اختصار (ابدأ/سطح المكتب) يجعل CWD = `C:\Windows\System32` → استثناء إقلاع قبل إنشاء النافذة → عملية خلفية | يُقرأ من `AppContext.BaseDirectory` + ضبط `CurrentDirectory` عند الإقلاع |
| 3 | **لا حارس تكرار**: كل نقرة على الاختصار تطلق عملية جديدة قد تتيمة في الخلفية | `Mutex` مسمى + قناة تفعيل: المحاولة الثانية تُظهِر نافذة النسخة الأولى (حتى لو مصغّرة) وتخرج فورًا |
| 4 | أي استثناء غير معالج قبل إنشاء النافذة = فشل صامت بلا أثر | معالجات `UnhandledException` (XAML/AppDomain/TaskScheduler) + سجل `fatal-.log` دائم + **نافذة خطأ عربية مرئية دائمًا** بدل البقاء الخلفي |

### حزام الأمان في المثبِّت نفسه

- الاختصارات تُنشأ بـ `WorkingDir: {app}` — فلا يعتمد صحة الإقلاع على سلوك دليل العمل.
- مجلد السجلات `%LOCALAPPDATA%\WERA_PRO_HD\logs` يُنشأ من المثبِّت قبل أول إقلاع.
- مكون VC++ Redist يغطي الحالة النادرة: ويندوز نظيف بلا تشغيليات C++ حديثة.

### إن ظهرت أي مشكلة رغم ذلك — خطة الفحص

| العرض | الملف الذي يكشف السبب | الإجراء |
|---|---|---|
| لا تظهر نافذة | `%LOCALAPPDATA%\WERA_PRO_HD\logs\fatal-.log` | السطر الأول يسمي السبب بالضبط (غالبًا عنوان API) |
| النافذة ظهرت ثم «لا يوجد اتصال بالخادم» | شريط حالة الدخول الصادق | تشغيل WeraPro API (`http://localhost:5400/` افتراضيًا) |
| تثبيت متوقف | سجل `%TEMP%\Setup Log*.txt` (شغّل الحزمة بـ `/LOG`) | راجع رسالة ISCC |
| التطبيق يعمل أصلًا | إدارة المهام → WeraPro.Desktop.exe | المحاولة الثانية ستُفعِّل نافذته الآن (الحارس) |

## أول دخول بعد التثبيت (First Login — تحديث 2026-11-11)

عند أول إقلاع على قاعدة بيانات جديدة ينشئ الخادم تلقائياً الحد الأدنى التشغيلي:

- **الفرع الرئيسي** + **محطة نقاط البيع 1** + **المخزن الرئيسي** + **درج المحطة**
- **حساب المالك**: اسم الدخول `owner` وكلمة المرور الافتراضية `Wera@2026`

خطوات أول تشغيل آمنة:

1. سجّل الدخول بـ `owner` / `Wera@2026` (تُختار الفروع والمحطات تلقائياً بعد الدخول).
2. من «المستخدمون والصلاحيات» غيّر كلمة مرور المالك فوراً.
3. أنشئ حسابات الموظفين بأدوارهم السبعة (كاشير/مشرف/أمين مخزن/محاسب/مدقق/مدير).
4. من «النسخ والصيانة» شغّل أول نسخة احتياطية كاملة وتحقق من حالتها VERIFIED.
5. راجع «الإعدادات» وقرارات D-01..D-18 الخاصة بنشاطك.

> لتخصيص كلمة مرور المالك قبل أول إقلاع: اضبط متغير البيئة
> `BOOTSTRAP__OWNERPASSWORD` (8 أحرف ورقم على الأقل) — راجع `PRODUCTION_BUILD.md` §4.1.
