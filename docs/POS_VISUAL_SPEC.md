# POS VISUAL SPEC — مواصفة نقطة البيع المرئية (G2)

> **الوثيقة:** WERA-PV-001 · **الإصدار:** 1.0 (G2 — للاعتماد) · **التاريخ:** 2026-11-01
> **المرجع الناظم:** GFM-CSharp 2.4.1 §9 (POS) و§5 (الوزن) و§7 (التصميم) و§29 (الطباعة) — بحسم المالك D-01/D-07/D-16 (2026-11-01)
> **القاعدة:** POS **نافذة مستقلة بلا أي قائمة إدارية** — كل الإدارة في Shell الإداري. الكاشير لا يرى إلا البيع.

## 2. تدفق الكاشير (Keyboard-first — الفأرة خيار احتياطي)

1. **المسح:** الحقل بؤرة التركيز الدائمة — أي باركود يُلحق فوراً كسطر؛ Exact Match ≤200ms (هدف p95 يُقاس في G13).
2. **صنف وزني؟** تفتح نافذة الوزن (C-43) تلقائياً حسب صيغة بيع الصنف (6 طرق — أدناه).
3. **تعديل السلة:** ↑↓ تنقل الصفوف · F2 وزن الصف المحدد · Delete مسح · Ctrl+D خصم (بحدود صلاحية D-06).
4. **عميل:** F3 بحث/إرفاق عميل (إلزامي للبيع الآجل فقط — D-05).
5. **الدفع:** F4 يفتح نافذة الدفع (C-44) — المستحق محسوباً، الوسائل المتاحة فقط.
6. **بعد الترحيل:** الإيصال يوجَّه تلقائياً إلى طابعة المحطة المعتمدة (80 أو 58 بقالبه المستقل — لا Print Dialog ولا تحويل تلقائي لـA4 §29.4)؛ نسخة الإدارة إلكترونياً.
7. **Reprint:** من شاشة سجل الفواتير بعلامة REPRINT واضحة وموافق مخوّل.

## 3. نافذة الوزن (D-07 المحسوم: دقة 1g · خطوة 5g)

تبويبات الطرق الست (كلها من `core.business_settings` لا ثوابت كود):

| # | الطريقة | السلوك |
|---|---|---|
| 1 | قراءة الميزان | زر «اقرأ» + آخر قراءة ووقتها؛ بلا ميزان مُعد: معطلة بسببها (`NOT_CONFIGURED`) لا مختفية |
| 2 | إدخال يدوي | NumberBox بدقة 1g، validation على خطوة 5g مع عرض «الدقيق 348g ← المعروض 350g» |
| 3 | **مبلغ مستهدف** | أدخل 70.00 ج.م ← الوزن = 350g (عند 200 ج.م/كجم) — تقريب الوزن لأقرب خطوة، والمبلغ يُعاد حسابه Banker's لأقرب قرش ويعرض الفرق إن حدث |
| 4 | وزن سريع | أزرار 100/250/350/500g… — **تخفى الأزرار التي تخالف خطوتها دقة الصنف** |
| 5 | باركود ملصق الوزن | يفك المتغير (prefix+PLU+وزن) ويعرض مصدره؛ بلا ملف معتمد: رفض موثق لا تخمين |
| 6 | عبوة موزونة | وزن العبوة الثابت من تعريف الصنف مع تحويل الوحدة |

**عرض الحساب الحي دائماً:** «السعر المرجعي 200.00 ج.م/كجم × 0.350 كجم = **70.00 ج.م**» + القيمة الدقيقة والمعروضة معاً + إثبات أن السعر **شامل الضريبة** (D-01) مع سطر فصل الضريبة عند الترحيل.

## 4. نافذة الدفع

- المستحق أعلى النافذة 32/700 + العملة منفصلة.
- وسائل الدفع: نقد (لوحة أرقام لمسية، أهداف ≥48px، الباقي بارز) · بطاقة (معطلة بوسم `BLOCKED_EXTERNAL_DEPENDENCY — بانتظار مزود D-11` حتى اعتماد Sandbox) · مختلط (Split واضح بتوزيع على وسيلتين) · آجل (لعملاء بحد ائتمان متاح فقط — يعرض الحد والمستحق D-05).
- منع التكرار: زر «تأكيد الدفع» يعطّل عند بدء الترحيل + Idempotency Key (§15.4) — لا ازدواج بيع/دفع/خصم مخزون.
- المرتجع/الاستبدال: مسار موثق بموافقة مشرف وسبب (D-04 توصية معتمدة كإعداد) والرد بوسيلة الدفع الأصلية.

## 5. حالات POS الإلزامية (تُصمم لا ترتجل)

| الحالة | العرض |
|---|---|
| Loading | skeleton لجدول السلة واللوحة — لا spinner مركزي |
| Empty (سلة فارغة) | «ابدأ بمسح باركود أو اضغط F1 للبحث» + آخر 3 فواتير للوردية |
| خطأ جلب صنف | صف الشريط يعرض رسالة + Retry — لا يتحول لسلة فارغة |
| انقطاع الاتصال | شريط علوي أحمر دائم «غير متصل — البيع متوقف» (D-08: Online-first، لا بيع Offline) + آخر تحديث |
| طابعة غير معدة | «الإيصال في قائمة الطباعة — طابعة المحطة غير معتمدة (G10)» لا فشل صامت |
| مخزون غير كافٍ | سطر برسالة السياسة المعتمدة (D-03 توصية: موافقة مشرف + سبب) |
| وردية مغلقة | قفل شاشة البيع مع توجيه «افتح وردية جديدة» |

## 6. قواعد سلوك صارمة
- **لا تختفي وظيفة بلا تفسير** — كل زر معطل يعرض سببه في Tooltip.
- النصوص المالية بعرض tabular ثابت؛ الأرقام LTR داخل RTL.
- لمس: أهداف ≥48px لكل ما يُستعمل أثناء الدفع؛ لوحة الوظائف F1..F12 ثابتة.
- لا حركة تعيق الإدخال: انتقالات ≤100ms واحترام تقليل الحركة.
- الصلاحيات: خصم فوق حد الدور ← طلب اعتماد مشرف بكلمة مروره وسبب (يسجل في التدقيق).
