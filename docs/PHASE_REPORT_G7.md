**اكتمل (وبُني واختُبر فعلياً — لا ادعاء):**

- **الشاشة المعتمدة من G2 بكامل أدوات الكاشير (بوابة القبول الأولى):** نافذة POS مستقلة بلا أي قائمة إدارية ولا شبكة منتجات (§9.0 ق1/ق2)، السلة الجدول المركزي بأعمدة الصنف/الكمية-الوزن بمصدره/السعر/الخصم/الإجمالي (§9.1C)، حقل الباركود بؤرة التركيز الدائمة مع Exact Match خادمي، شريط سياق المحطة (وردية/محطة/كاشير/اتصال حقيقي)، لوحة مجاميع **من الخادم فقط** (§9.0 ق10 — المعاينة تعاد بعد كل تغيير عبر `POST /pos/preview` ولا حساب مالي في ViewModel إطلاقاً)، وشريط F-keys بالاختصارات النصية للمواثيق §9.10.
- **الباركود والبحث والعميل واستعلام المخزون وتحرير السلة (§9.2):** الالتقاط بالباركود المنمّط/SKU/PLU (Exact Match)، بحث نصي مرقم خادمياً محدود، اختيار عميل لا يفقد السلة (CustomerPicker)، المتاح (رصيد−محجوز) معروض مع كل التقاط، وتحرير السلة (كمية/حذف/خصم سطر يخضع لحد الدور خادمياً D-06).
- **الوزن بالطرق الست (بوابة القبول · §9.3/§5):** (1) قراءة الميزان بحالاتها الصادقة — **مستقرة تُقبل، وغير مستقرة/قديمة (>10ث)/منقطعة تُرفض برموز موثقة** (الاختبار الإلزامي 7 بالأوجه الأربع)؛ (2) إدخال يدوي مصرح بمصدر MANUAL_WEIGHT لا يوصف كقراءة ميزان؛ (3) **المبلغ المستهدف: 200 ج.م/كجم × 70 ج.م = 350 جم قبل سياسة التقريب حرفياً** (D-07 — الحساب من `WeightCalculator` خادمياً والقيمة الدقيقة والمعروضة تحفظان معاً)؛ (4) وزن سريع بأزرار لا تظهر إن خالفت خطوة الصنف؛ (5) **باركود الملصق الموزون** يُحلل بملفات `vw_barcode_profiles` المعتمدة فقط — البادئة/الطول/رقم التحقق مجهولة = **رفض موثق لا تخمين** (§5.3)، والوزن يضاف بمصدر WEIGHT_LABEL؛ (6) العبوة الموزنة تسلك PACK. الحدود (min/max/الصفر/السالب) مفروضة في كل المسارات، والسطر يحفظ الوزن والمصدر ووحدة الإدخال ومعامل التحويل والكمية الأساسية وسعر الوحدة والمبلغ ومصدر الوزن (§9.3 «قواعد الحساب»).
- **الدفع نقداً وبطاقة ومختلطاً وآجلاً (بوابة القبول · §9.6):** نقدي بالفكة المميزة عن المستحق (§9.1F)، **مختلط** بتوزيع على وسيلتين مع رفض النقص (PAYMENT_TOTAL_MISMATCH)، **آجل** بعميل إلزامي + حد ائتمان يُشتق من الدفتر + صلاحية sales.credit.sell (D-05: آلية كاملة، والتمكين لكل عميل قرار موثق — العميل الاختباري مفعّل والحد 500)، **وبطاقة عبر Sandbox موثقة**: الإعداد الافتراضي `NOT_CONFIGURED` يرفض بوضوح (B-02/D-11)، وعند ضبطه `SANDBOX_SIMULATOR` يعمل المسار كاملاً عبر بوابة محاكاة **موسومة بوضوح** (`provider_name='WeraSandbox-SIMULATED'` + مرجع `SBX-…`) مع تعويض الشحن عند فشل ترحيل الفاتورة — **لا ادعاء مزود حقيقي؛ الجهاز الحقيقي عند حسم D-11 ورفع B-02** (البطاقة الحقيقية اختبار G10 أيضاً).
- **الفواتير والتعليق والاستعادة والطباعة الاختيارية والمرتجعات والاستبدال (§9.8/§9.5):** التعليق بلقطة JSONB كاملة والاستعادة **قراءة لا تنشئ بيعاً ولا دفعاً ولا حركة** (مختبر بالعد قبل/بعد)، والاستعادة الثانية مرفوضة. **المرتجع مرتبط بالأصل**: اعتماد مشرف إلزامي (قيد V005 + طلب من الكاشير وقرار المشرف — فصل واجبات `approvals_no_self`)، السبب ≥3 محارف، **الرد بوسيلة الدفع الأصلية (البطاقة للبطاقة — D-04)** والرد النقدي لقيمة بطاقة يتطلب السياسة المعتمدة + صلاحية sales.refund.cash_for_card، الحد الأقصى ما بيع ولم يُرجع (مشغل `tf_refund_line_guard`)، إعادة التخزين SALE_RETURN اختيارية (الهالك لا يعود رصيداً)، والاستبدال = مرتجع + فاتورة جديدة بالفرق (مختبر).

## 5. قرار البوابة

**`READY_FOR_OWNER_REVIEW_WITH_B05_CONDITION`**

G7 مكتملة البناء والاختبار بدقة: الخادم مبني Release ومختبر بالكامل (**مجال 196/196 · بنية تحتية 36/36 · API 100/100 × 3 دورات كاملة** — منها اختبارات G7 الـ18 التي تنفذ الاختبارات الإلزامية الثلاثة عشر حرفياً بأرقام مرجعية مستقلة — و**قيود V018: 85 PASS + 1 ENV من 86** بتصريح trgm الصادق نفسه)، وكود Desktop كامل بكل فحوص Linux الممكنة (19/19 XML · 4/4 صياغة)، وبقيت **اللقطات فقط** معلقة على بيئة Windows (B-05 — الالتزام المكفول: لقطات G2..G7 دفعة واحدة عند أول بيئة، قبل التعميم على بقية الوحدات).

**المطلوب:** أمر المالك «اعتمد G7» (فيلتزم تسليم اللقطات عند توفر البيئة كنمط الاعتماد المشروط السابق)، أو توجيهات تعديل — ثم تفتح **G8 (الورديات/النقد/الأدراج/المصروفات/رأس المال)** بأمر «كمل G8».

## 6. الطلب

**هل تعتمد G7 بشرطها المعلق (اللقطات عند رفع B-05) أم تطلب تعديلات؟**

- بالاعتماد (مثل «اعتمد G7»): تُفتح **G8 — الورديات والنقد والأدراج والمصروفات ورأس المال** فوراً، ويبقى التزام لقطات G2..G7 مكفولاً عند أول بيئة Windows.
- بالتعديل: يبقى العمل داخل G7 (Revision) على أساس الحل القائم.
- يُستحسن مع الاعتماد: **توفير جهاز/VM Windows** (رفع B-05 — يفتح لقطات G2..G7 المعلقة دفعة واحدة)، و**حسم D-11 (مزود الدفع والبنك وتفعيل Sandbox المزود)** لتشغيل البطاقة الحقيقية بعد المحاكاة الموسومة، و**D-14 (الأرصدة الافتتاحية)** لأنها شرط جوهري لبوابة G8 (B-04).
